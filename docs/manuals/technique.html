01Vue d’ensemble

LeadFinder trouve des entreprises à partir d’un lien Google Maps (ou d’un mot-clé et d’un lieu), sépare celles qui ont un site web de celles qui n’en ont pas, puis aide à les démarcher : collections de prospects, propositions par e-mail ou WhatsApp, maquettes de page d’accueil générées par IA et exports Excel/CSV.

Les quatre composants en production

ComposantRôle
webL’application Next.js : pages, connexion, API REST (/api/v1/…). Démarre les recherches et les exports en les plaçant dans une file d’attente.
workerProcessus d’arrière-plan : exécute les recherches (Google ou données d’exemple), visite les sites des entreprises pour trouver e-mails et réseaux sociaux, génère les gros exports, fait le ménage toutes les 10 minutes (suppression des résultats Google expirés, des fichiers d’export périmés…).
PostgreSQL 16Toutes les données (utilisateurs, recherches, collections, propositions, maquettes, journaux) et la file d’attente des tâches (pg-boss).
CaddyReverse proxy devant l’application : certificat HTTPS automatique (Let’s Encrypt) et adresse IP du visiteur fiable pour les limites anti-abus.

Technologies

CoucheChoix
Interface et APINext.js 16 (App Router), React 19, TypeScript strict, Tailwind CSS 4
Base de donnéesPostgreSQL 16 + Drizzle ORM (migrations SQL versionnées dans drizzle/)

02Prérequis

Ce qu’il faut réunir avant de commencer. La méthode recommandée — un petit serveur virtuel (VPS) avec Docker — fonctionne chez n’importe quel hébergeur et garde vos données chez vous.

Un serveur (VPS)

  • Ubuntu 24.04 LTS
  • 2 vCPU, 4 Go de RAM, 40 Go de disque (minimum confortable)
  • Adresse IPv4 publique
  • Hébergeurs possibles : Hetzner, OVHcloud, DigitalOcean, Scaleway, Contabo… (comptez en général 5 à 15 € par mois ; vérifiez les tarifs actuels)

Un nom de domaine

  • Par exemple leads.mon-agence.com
  • Accès à la zone DNS pour créer un enregistrement A
  • Indispensable pour le HTTPS automatique

Google Cloud (pour les vraies données)

  • Un compte Google Cloud avec facturation activée
  • L’API « Places API (New) » (voir chapitre 4)
  • Sans clé, l’application tourne en mode « données d’exemple »

Vercel AI Gateway (facultatif)

  • Un compte Vercel et une clé AI Gateway (chapitre 5)
  • Sans clé, propositions et maquettes utilisent des modèles intégrés
Pourquoi un VPS plutôt qu’une plateforme « tout-en-un » ?

LeadFinder a besoin de deux processus qui tournent en permanence (web et worker) et d’un dossier partagé entre eux pour les fichiers d’export. Les plateformes serverless (Vercel, Netlify…) ne conviennent pas au worker. Les plateformes à conteneurs (Railway, Render, Fly.io) fonctionnent à condition de lancer web et worker dans le même service ou de partager un disque : c’est possible mais moins simple. Le VPS avec Docker Compose est la voie testée et documentée ici.

Avant de mettre en ligne

La configuration Docker a été écrite avec soin et les commandes qu’elle lance ont été exécutées et testées, mais l’image Docker elle-même n’a pas pu être construite dans l’environnement de développement (pas de démon Docker). Faites la première installation sur un serveur de test ou suivez attentivement l’étape « Vérifier » du chapitre 3.

03Mettre l’application en ligne

Installation complète sur un VPS Ubuntu avec Docker Compose. Remplacez leads.mon-agence.com par votre domaine et 203.0.113.10 par l’adresse IP de votre serveur.

Étape 1 — Pointer le domaine vers le serveur

Dans la zone DNS de votre domaine, créez un enregistrement :

TypeNomValeurTTL
Aleads203.0.113.10300

La propagation prend de quelques minutes à quelques heures. Vérifiez avec ping leads.mon-agence.com : la réponse doit venir de l’IP de votre serveur.

Étape 2 — Préparer le serveur

Connectez-vous en SSH puis mettez le système à jour et activez le pare-feu :

ssh root@203.0.113.10

apt update && apt upgrade -y
# Pare-feu : SSH, HTTP et HTTPS uniquement
ufw allow OpenSSH && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable

# Un utilisateur dédié (évitez de tout faire en root)
adduser deploy && usermod -aG sudo deploy

Étape 3 — Installer Docker

# Script officiel d’installation de Docker Engine + Compose
curl -fsSL https://get.docker.com | sh
usermod -aG docker deploy

# Reconnectez-vous en tant que deploy, puis vérifiez :
docker --version && docker compose version

Étape 4 — Récupérer le code

cd ~
git clone https://github.com/siaoctawacta/Webscrapper.git leadfinder
cd leadfinder

Étape 5 — Créer le fichier de configuration .env

Copiez le modèle puis générez les secrets :

cp .env.example .env

openssl rand -base64 32   # → BETTER_AUTH_SECRET
openssl rand -hex 24      # → SETUP_TOKEN
openssl rand -hex 24      # → POSTGRES_PASSWORD (lettres et chiffres uniquement)

nano .env

Valeurs minimales à renseigner (les autres ont des valeurs par défaut raisonnables, voir chapitre 6) :

APP_ENV=production
APP_URL=https://leads.mon-agence.com
DOMAIN=leads.mon-agence.com

BETTER_AUTH_SECRET=<le premier secret généré>
SETUP_TOKEN=<le deuxième secret>
POSTGRES_PASSWORD=<le troisième secret>

SIGNUP_MODE=invite
GOOGLE_MAPS_API_KEY=<votre clé Google, ou vide pour le mode exemple>
AI_GATEWAY_API_KEY=<votre clé AI Gateway, ou vide>
Important
  • Ne laissez aucune valeur <managed-secret> : remplacez-les toutes ou videz-les.
  • POSTGRES_PASSWORD est fixé à la première création de la base : changez-le avant le premier lancement.
  • Ne versionnez jamais le fichier .env (il est déjà exclu par .gitignore).

Étape 6 — Lancer

docker compose up -d --build

Docker construit l’image, démarre PostgreSQL, applique les migrations de la base (service migrate), puis lance web, worker et le proxy proxy (Caddy). Caddy obtient le certificat HTTPS automatiquement dès que le DNS pointe vers le serveur.

docker compose ps                       # tous les services "running" (migrate "exited (0)")
docker compose logs -f web worker proxy # Ctrl+C pour quitter

Dans les journaux du worker vous devez voir [worker] ready — search concurrency 4.

Étape 7 — Créer le compte administrateur

Ouvrez dans votre navigateur :

https://leads.mon-agence.com/sign-up?setup=<votre SETUP_TOKEN>

Le premier compte créé avec ce lien devient l’administrateur. Sans le bon jeton, la création du premier compte est refusée en production — personne ne peut prendre la place de l’administrateur en s’inscrivant avant vous.

Étape 8 — Inviter l’équipe

Dans Admin → Invitations, saisissez l’e-mail de la personne et son rôle, puis copiez le lien d’invitation personnel affiché (il n’est montré qu’une fois) et envoyez-le-lui. Avec SIGNUP_MODE=approval, n’importe qui peut aussi s’inscrire mais doit être approuvé dans Admin → Users.

Étape 9 — Vérifier

  1. Ouvrez https://leads.mon-agence.com : le cadenas HTTPS s’affiche et la page de connexion apparaît.
  2. Lancez une petite recherche (20 résultats) avec un lien Google Maps. Elle doit passer à Completed en moins d’une minute.
  3. Sans clé Google, un bandeau jaune « Sample data mode » est affiché : les entreprises sont fictives. Avec une clé, vérifiez que les noms correspondent bien à ce que montre Google Maps.
  4. Enregistrez quelques résultats dans une collection, puis faites un export Excel : le fichier doit se télécharger.
Sans nom de domaine (test rapide)

Laissez DOMAIN vide et mettez APP_URL=http://203.0.113.10 : l’application est servie en HTTP simple sur le port 80. À réserver aux essais : sans HTTPS, les mots de passe circulent en clair.

04Configurer Google Maps Platform

LeadFinder interroge Google uniquement via l’API officielle « Places API (New) ». Il ne lit jamais les pages de Google Maps. Chaque requête est facturée sur votre compte Google Cloud.

Créer la clé

  1. Allez sur console.cloud.google.com, créez un projet (par ex. « LeadFinder ») et associez-lui un compte de facturation.
  2. Menu APIs & Services → Library : cherchez Places API (New) et cliquez sur Enable. (L’ancienne « Places API » ne suffit pas.)
  3. APIs & Services → Credentials → Create credentials → API key.
  4. Restreignez la clé : API restrictions → uniquement Places API (New) ; Application restrictions → IP addresses → l’IP publique de votre serveur.
  5. Dans Billing → Budgets & alerts, créez un budget mensuel avec alertes (par ex. à 50 %, 90 % et 100 %).
  6. Copiez la clé dans GOOGLE_MAPS_API_KEY du fichier .env, puis docker compose up -d.

Comprendre les coûts

Google renvoie au maximum 20 résultats par requête et environ 60 par recherche. Pour aller au-delà, LeadFinder découpe automatiquement la zone de carte en carrés plus petits (jusqu’à ~300 m de côté) et interroge chacun. Les estimations ci-dessous sont calculées par l’application avec le prix configuré (GOOGLE_TEXT_SEARCH_PRICE_PER_1000, 35 $ par défaut). Le nombre réel dépend de la densité de la zone.

Résultats demandésRequêtes estiméesCoût estimé

50044≈ 1,54 $
1 00084≈ 2,94 $
5 000404≈ 14 $

  • Google accorde un quota mensuel gratuit (de l’ordre de 1 000 requêtes Text Search Enterprise par mois au moment de la rédaction) : vérifiez la page de tarification officielle, qui évolue.
  • Au-delà de COST_CONFIRM_THRESHOLD_USD (5 $ par défaut), l’application demande une confirmation avant de lancer la recherche.
  • Chaque utilisateur a une limite mensuelle de requêtes facturables (MONTHLY_PROVIDER_REQUEST_LIMIT_PER_USER, 5 000 par défaut, ajustable par personne dans Admin).
  • Toutes les requêtes et leur coût estimé apparaissent dans Admin → Usage. La facture réelle est celle de Google Cloud.

Ce que l’application conserve (conditions de Google)

Donnée GoogleTraitement
Résultats de rechercheConservés GOOGLE_RESULTS_RETENTION_HOURS heures (24 par défaut) pour trier, filtrer et choisir, puis supprimés automatiquement.
Prospects enregistrésSeuls l’identifiant du lieu et le lien Google Maps sont stockés. Nom, téléphone, adresse, note… sont rechargés en direct à l’affichage d’une collection (requête « Place Details » facturée, comptée dans la limite mensuelle).
ExportsPour les lignes Google : lien Maps, identifiant du lieu et vos propres données (e-mails trouvés sur les sites, statut, tags, notes). Les champs Google sont laissés vides avec l’explication dans la feuille « Data Quality ».

Changer cette règle

Si vous disposez d’un autre accord avec Google ou d’un fournisseur de données sous licence autorisant le stockage et l’export, la règle se modifie à un seul endroit : src/server/providers/policy.ts. Faites-le en connaissance de cause.

05Configurer l’IA (Vercel AI Gateway)

L’IA sert à « polir » les propositions et à rédiger les maquettes de page d’accueil. Elle est facultative : sans clé, des modèles de texte intégrés (anglais et français) sont utilisés.

  1. Créez un compte sur vercel.com, ouvrez AI Gateway et créez une clé API.
  2. Renseignez AI_GATEWAY_API_KEY dans .env. Optionnel : AI_MODEL (par défaut anthropic/claude-sonnet-5.5, tout modèle proposé par la passerelle fonctionne).
  3. Ajustez AI_DAILY_LIMIT_PER_USER (50 générations par personne et par jour par défaut).
  4. Redémarrez : docker compose up -d. L’interrupteur « Polish with AI » devient actif.

Garde-fous

  • L’IA ne reçoit que des faits connus sur l’entreprise, placés dans un bloc de données qu’elle doit traiter comme non fiable (protection contre l’injection de consignes via le texte d’un site).
  • Les réponses sont validées par schéma. Une proposition réécrite qui invente des chiffres, des liens ou des e-mails, ou qui perd la signature, est rejetée et remplacée par le modèle intégré.
  • Les maquettes sont rendues en HTML statique sûr : tout texte est échappé, aucun script, politique de sécurité de contenu stricte.

07Architecture

Le dépôt est un seul projet TypeScript. Le contrat entre les modules est décrit dans docs/ARCHITECTURE.md ; ce chapitre en résume l’essentiel.

Déroulement d’une recherche

  1. Lecture du lien. src/server/maps-link extrait le terme recherché et la zone visible du lien Google Maps (ex. /maps/search/hôtel/@6.14,1.16,12z → « hôtel », zone de ≈ 49 × 30 km). Les liens courts maps.app.goo.gl sont résolus en suivant uniquement des redirections vers des domaines Google, sans lire de page.
  2. Création. L’API valide la demande, applique les limites (verrou par utilisateur pour éviter les dépassements en parallèle), estime le coût, enregistre la recherche et la place dans la file search.run.
  3. Exécution (worker). Le fournisseur (Google ou exemple) renvoie les résultats page par page ; au-delà de 60, la zone est découpée en quadrillage adaptatif. Chaque résultat est normalisé (téléphone au format international, site, qualité) et dédoublonné par identifiant Google.
  4. Enrichissement. Pour chaque entreprise qui a un site, src/server/enrichment visite la page d’accueil et au plus deux pages contact/à propos : e-mails publiés, réseaux sociaux, HTTPS, compatibilité mobile, année du ©. Respect de robots.txt, une requête à la fois par site, blocage des adresses réseau privées (anti-SSRF).
  5. Finalisation. Détection des doublons probables (même téléphone, même site, ou nom très proche à moins de 80 m), statut final et date d’expiration des résultats.

08Exploitation au quotidien

Mettre à jour l’application

cd ~/leadfinder
git pull
docker compose up -d --build   # reconstruit l’image ; les migrations s’appliquent automatiquement
docker compose ps

Le service migrate applique les nouvelles migrations de base de données avant le redémarrage de web et worker. Faites une sauvegarde juste avant une mise à jour importante.

Sauvegarder la base de données

# Sauvegarde ponctuelle (fichier compressé daté)
mkdir -p ~/backups
docker compose exec -T db pg_dump -U leadfinder leadfinder | gzip > ~/backups/leadfinder-$(date +%F).sql.gz

# Sauvegarde quotidienne à 3 h du matin (crontab -e) et conservation 14 jours
0 3 * * * cd ~/leadfinder && docker compose exec -T db pg_dump -U leadfinder leadfinder | gzip > ~/backups/leadfinder-$(date +\%F).sql.gz && find ~/backups -name '*.sql.gz' -mtime +14 -delete

Copiez régulièrement les sauvegardes hors du serveur (stockage objet, autre machine). Les fichiers d’export sont temporaires (24 h) et n’ont pas besoin d’être sauvegardés.

Restaurer une sauvegarde

docker compose stop web worker
gunzip -c ~/backups/leadfinder-2026-11-15.sql.gz | docker compose exec -T db psql -U leadfinder -d leadfinder
docker compose start web worker

Pour une restauration complète, restaurez dans une base vide (recréez le volume pgdata ou une nouvelle base) afin d’éviter les conflits.

Journaux et surveillance

docker compose logs -f --tail=200 web worker   # journaux en direct
docker compose logs proxy | tail -50            # HTTPS / certificats
docker stats                                    # CPU et mémoire
df -h                                           # espace disque
  • Configurez une surveillance de disponibilité (UptimeRobot, Better Stack…) sur https://votre-domaine/sign-in.
  • Le worker n’a pas de page web : surveillez ses journaux. Une recherche bloquée en « Queued » signifie que le worker ne tourne pas.
  • Admin → Audit log trace les recherches, enregistrements, exports, téléchargements et actions d’administration.

Réinitialiser le mot de passe d’un utilisateur

L’application n’envoie pas d’e-mails, il n’y a donc pas de lien « mot de passe oublié ». Depuis le serveur :

docker compose exec web node_modules/.bin/tsx --tsconfig tsconfig.worker.json \
  src/scripts/set-password.ts personne@exemple.com 'nouveau-mot-de-passe-10-car'

La personne est déconnectée de tous ses appareils. Communiquez-lui le nouveau mot de passe par un canal sûr et demandez-lui de le changer.

Monter en charge

  • Plus de recherches simultanées : augmentez MAX_CONCURRENT_JOBS et la mémoire du serveur.
  • Un second worker sur la même machine : docker compose up -d --scale worker=2 (les tâches sont réparties automatiquement).
  • PostgreSQL géré (Neon, Supabase, RDS…) : renseignez son DATABASE_URL dans les services et retirez le service db.

09Sécurité

Mesures intégrées à l’application, puis ce qui reste de votre responsabilité.

Déjà en place

  • Accès : aucune adresse e-mail seule ne donne de droits. Premier administrateur via SETUP_TOKEN ; invitations par lien secret à usage unique lié à l’e-mail ; nouveaux comptes en attente d’approbation selon SIGNUP_MODE.
  • Connexion : mots de passe hachés, limite de tentatives par compte (10 par 15 min) et par IP, comptes désactivés bloqués immédiatement (sessions supprimées, recherches annulées).
  • Données : chaque requête vérifie que la ressource appartient à l’utilisateur ; tris et filtres sur liste blanche ; requêtes SQL paramétrées.
  • Visites de sites : robots.txt respecté, adresses réseau privées bloquées à chaque redirection, taille et durée limitées.
  • Exports : cellules protégées contre l’injection de formules ; liens de téléchargement à durée courte, liés au propriétaire.
  • Maquettes partagées : HTML échappé, aucun script, politique de sécurité de contenu stricte, non indexées.
  • Coûts : limites mensuelles par personne, confirmation des recherches coûteuses, rechargements Google limités par la même allocation.
  • Une revue de sécurité indépendante a été menée ; les 5 problèmes trouvés ont été corrigés et couverts par des tests.

À votre charge

  • Secrets forts et uniques dans .env ; accès SSH par clé (désactivez la connexion par mot de passe) ; mises à jour système régulières (unattended-upgrades).
  • Clé Google restreinte à Places API (New) et à l’IP du serveur ; alertes de budget actives.
  • Sauvegardes chiffrées et stockées hors du serveur ; test de restauration de temps en temps.
  • Respect des lois sur les données personnelles et la prospection (par ex. la loi togolaise de 2019 sur la protection des données à caractère personnel, le Data Protection Act 2012 du Ghana, le RGPD pour les contacts européens) : n’utilisez que les coordonnées professionnelles publiées, identifiez-vous clairement et respectez toute demande de ne plus être contacté.

12Limites connues et aide-mémoire

Limites connues

  • Les appels réels à Google Places et à l’AI Gateway n’ont pas pu être testés dans l’environnement de développement (pas de clés ni d’accès réseau à ces services) : ils sont couverts par des tests avec des réponses enregistrées. Commencez par de petites recherches.
  • L’image Docker n’a pas été construite dans l’environnement de développement (voir chapitre 2).
  • Google renvoie au plus ~60 résultats par requête : les grands volumes reposent sur le découpage de la carte, et le nombre final dépend des entreprises réellement présentes dans la zone.
  • Dans les collections, le tri et le filtre sur les champs Google (nom, téléphone…) ne fonctionnent que pour les sources autorisant le stockage.
  • Pas d’envoi d’e-mails par l’application (invitations, réinitialisation de mot de passe, propositions) : vous envoyez vous-même depuis votre messagerie ou WhatsApp.
  • L’interface est en anglais ; les propositions et maquettes sont disponibles en anglais et en français.
